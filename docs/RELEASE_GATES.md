# VaultX release gates

**Overall status: BLOCKED. Use disposable test files only. Do not store irreplaceable private files or other genuine secrets in VaultX until every gate below passes on the intended production configuration.** This document is the release decision checklist for [PRD §§8, 15–16 and 21](../prd.md). The [full requirement audit](PRD_AUDIT.md) and [13-journey acceptance record](ACCEPTANCE_MATRIX.md) give component-level evidence. A passing unit test, local browser test, or small live-provider probe does not by itself pass a production gate.

To mark a gate **PASS**, record the command or manual procedure, date, production host and domain, browser/device, disposable fixture, observed result, and redacted evidence. Verify actual Atlas and Cloudinary state where the gate calls for it. Never include passwords, keys, tokens, personal filenames, file contents, signed URLs, or `.env.local` in a report. If any required result fails or remains unverified, keep that gate **BLOCKED** and keep overall release **BLOCKED**.

Active-store deletion means VaultX has removed the tracked active Cloudinary objects and MongoDB records. Previously issued signed CDN responses may persist during invalidation; Cloudinary/MongoDB backups, browser downloads, screenshots and disconnected offline copies are outside immediate active-store erasure. Explain those limits to the owner and check provider retention settings before accepting the deletion gate.

The owner must rotate MongoDB and Cloudinary credentials previously shared in chat and change the owner login password if the proposed password was used. Keep replacements only in ignored local configuration and private host settings. Until every row is supported by production evidence, the release decision stays **BLOCKED**.
